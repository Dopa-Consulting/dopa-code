# test_driven_development

RED-GREEN-REFACTOR. Escribir tests primero, verlos fallar, escribir codigo minimo, verlos pasar.

**Origen**: obra/superpowers
**Tags**: general, testing, tdd, universal

## Steps

1. RED: escribir test que falle
2. Verificar que el test falla por la razon correcta
3. GREEN: escribir el minimo codigo para que pase
4. REFACTOR: mejorar el codigo sin romper tests
5. Commit despues de cada ciclo

## Best Practices

- Nunca escribir codigo antes que el test
- Cada test prueba una sola cosa
- Eliminar codigo escrito antes de los tests
- Tests unitarios > tests de integracion > E2E
